Two-step assembly

Round 1 — target PCR. Gene primers carry universal tails: F = CS1 + geneF, R = CS2 + geneR. Product = CS1–amplicon–CS2. No barcodes or adapters yet; every amplicon now shares the same CS1/CS2 handles.

Round 2 — barcoding PCR. Primers anneal to CS1/CS2 and append the sample barcode + platform adapter: P_fwd = adapter + barcode_i + CS1, P_rev = adapter + barcode_j + CS2. Because these primers prime on the constant CS1/CS2 (not on the genome), they are panel-agnostic and add the same barcodes to every amplicon in the pool.

Design consistency — no conflict (verified)

The barcode set was checked against every other sequence in the construct and the target genomes:
  • ✓ barcode set orthogonality — min pairwise Hamming = 10 (safe for 2-mismatch demux)
  • ✓ barcodes vs CS1 / CS2 — ≥ 8 nt different (worst case) → CS-anchored demux is unambiguous
  • ✓ barcodes vs all 575 panel primers — 0 within 3 mismatches → no mispriming risk
  • ✓ CS1 / CS2 in the pan-reference (6 nuclear + 6 mito + human) — 0 occurrences (all 4 orientations) → CS tails never prime on target DNA
Re-run the check any time barcodes change: analysis/bin/check_barcode_conflicts.py.
What was designed where. The panel-design work fixed the scheme (CS1/CS2 tags, a combinatorial dual 24-nt barcode plan) and the gene primers + targets — those are native. The actual barcode sequences were finalised here as an orthogonal, conflict-checked set (generate_barcodes.py → barcodes_96.tsv); swap in your reagent barcodes for a real run and re-run the check. CS1/CS2 and the sequencing adapters are standard external sequences, deliberately chosen so the barcoding chemistry is off-the-shelf.
